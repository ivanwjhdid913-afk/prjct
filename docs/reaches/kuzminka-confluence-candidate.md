# Кузьминка — Воронеж у Большой Кузьминки

**Статус на 15.11.2026 — картографически обоснованный кандидат.** Устье подтверждается официальным каталогом и топологией OSM. Для включения в расчёт нужно установить параметры потока, условия смешения и пригодность нижней границы. Соединение с действующим участком потребовало бы учесть дополнительную протоку с разделением потока и боковую связь.

## Общий узел и направления

Кузьминка — правый приток Воронежа у села Большая Кузьминка. Роскадастр приводит запись № **0079427**, лист N-37-116, координаты **52°46′, 39°43,8′** с точностью каталога. Устье у села также отмечено в краеведческом атласе. [Государственный каталог географических названий, стр. 38](https://kadastr.ru/upload/export_kadastr_files/%D0%9B%D0%B8%D0%BF%D0%B5%D1%86%D0%BA%D0%B0%D1%8F%20%D0%BE%D0%B1%D0%BB%D0%B0%D1%81%D1%82%D1%8C_201.pdf), [История Большекузьминского сельского поселения](https://iatlas.borinskoe-lib.ru/?page_id=1617).

В сохранённой выгрузке OSM общий узел **2106156604 v3** имеет координаты WGS84 **[39.7309146, 52.7680180]** в порядке долгота, широта. Он входит в ось Воронежа `35164443 v29` на индексе 354 и завершает ось Кузьминки `131324032 v16` на индексе 338. Воронеж проходит через узел, Кузьминка заканчивается в нём. Третья линия, ссылающаяся на тот же узел, — `342561439 v4` с тегом `boundary=administrative`. Это часть границы Липецкого и Добровского муниципальных округов. [Узел OSM](https://www.openstreetmap.org/node/2106156604/history/3), [ось Воронежа](https://www.openstreetmap.org/way/35164443/history/29), [ось Кузьминки](https://www.openstreetmap.org/way/131324032/history/16), [административная граница](https://www.openstreetmap.org/way/342561439/history/4).

Кузьминка подходит с запада к правому берегу Воронежа. Воронеж подходит с северо-востока и после устья идёт на юг с местными поворотами русла. Это согласуется с порядком вершин обеих осей, правилом OSM направлять ось водотока от истока к устью и описанием течения Воронежа в Добровском округе. Эти сведения устанавливают общее направление стока. Скорость и возможные местные изменения направления не измерялись. [Правило OSM](https://wiki.openstreetmap.org/wiki/Key:waterway), [описание Добровского округа](https://lipkray.ru/dobroe/priroda), [описание Липецкого округа](https://lipkray.ru/lipetskr/priroda).

## Снимок и пределы проверки

Просмотрен сохранённый обзор Esri World Imagery с рамкой EPSG:4326 `[39.725, 52.72882352941177, 39.762, 52.77017647058824]`, размером 1700 × 1900. На обзоре открытое русло Воронежа видно выше и ниже устья, а ниже по течению виден открытый вход в боковую протоку. Заросшее русло Кузьминки подходит к правому берегу в районе устья. Растительность у берега закрывает часть русла притока, поэтому непрерывность открытой воды до оси Воронежа и положение устья с точностью OSM по этому снимку не определены. Видимых мостов или поперечных плотин в границах короткой схемы не замечено. Дата съёмки мозаики неизвестна. [Сервис Esri World Imagery](https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer).

В открытом гидрологическом бюллетене есть данные постов Воронежа в Липецке. Обзор многолетних измерений также использует городской пост. Для устья и трёх предложенных створов не найдено синхронных измерений расходов двух приточных ветвей, местных уровней, сечений и скоростей. По имеющимся данным неизвестны расстояние до полного поперечного смешения, условия подпора и обмен водой с поймой. Створ нижнего Воронежа выше протоки можно проверить на месте. Для включения в расчёт потребуются проверка открытого русла и сооружений, местные данные для выбранного режима, обоснование длины нижней ветви и граничного условия. Для связи с существующим участком также нужны наблюдения на протоке и боковом соединении. [Бюллетень ЦЧ УГМС](https://www.ugms-cho.ru/lipeck/gidrologicheskij-byulleten/), [Дмитриева и Дюкарев, 2024](https://journals.vsu.ru/geo/ru/article/view/12704).

```powershell
@'
from xml.etree import ElementTree as ET
from geographiclib.geodesic import Geodesic

osm = ET.parse("backend/data/raw/voronezh-kuzminka-context.osm").getroot()
nodes = {
    node.get("id"): (float(node.get("lat")), float(node.get("lon")))
    for node in osm.findall("node")
}
ways = {
    way_id: [node.get("ref") for node in osm.findall(f"way[@id='{way_id}']/nd")]
    for way_id in ("35164443", "131324032")
}
voronezh, kuzminka = ways["35164443"], ways["131324032"]
assert set(voronezh[350:361]) & set(kuzminka[333:339]) == {"2106156604"}
assert voronezh[354] == kuzminka[338] == "2106156604"
assert [kuzminka[-1]] == kuzminka[338:339]
for way, start, end in (
    (voronezh, 350, 354), (kuzminka, 333, 338),
    (voronezh, 354, 358), (voronezh, 358, 360),
    (voronezh, 354, 361), (voronezh, 354, 373),
    (voronezh, 354, 390), (voronezh, 354, 392),
):
    points = [nodes[ref] for ref in way[start : end + 1]]
    length = sum(
        Geodesic.WGS84.Inverse(*a, *b)["s12"]
        for a, b in zip(points, points[1:])
    )
    print(f"{way[start]} → {way[end]}  {length:.3f} m")
```
