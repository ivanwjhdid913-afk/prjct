# Контроль аналитики контрольных точек

Использованы физические параметры существующей демонстрации двух источников на Дону без изменений: Qr=10 м³/с, cb=10 мг/л, u=0,25 м/с, D=5 м²/с, горизонт 6 ч. Источник 1: x=0 м, q=0,1 м³/с, ce=100 мг/л в 0–0,5 ч. Источник 2: x=1200 м, q=0,05 м³/с, ce=60 мг/л в 2–2,5 ч. Вне периодов ce=cb, водный поток сохраняется. Все нагрузки и гидрология сценарные.

Порог **10,2 мг/л — пользовательский сценарный**, не официальный норматив. Контрольные номера 36, 50, 100 соответствуют внутренним индексам 35, 49, 99. Значения — средние существующих расчётных сегментов, не измерения в точке.

## Алгоритм

Анализируется линейная интерполяция между реальными неравномерными сохранёнными состояниями, как при воспроизведении. Правило строгое C(t)>H. Пересечения вычисляются внутри интервала, а не округляются к кадру. Первое достижение одинакового максимума — самое раннее. Касание H не является превышением; касание из области выше H разделяет два открытых периода. Превышение в начале отличается от последующего пересечения снизу. Превышение на последнем моменте помечено как продолжающееся; за горизонт ничего не экстраполируется.

## Измеренный контроль сохранения траектории

Контрольная запись содержит все 3699 обычных внутренних состояний той же неизменённой схемы; выдача — 178 состояний. Данные обоих рядов независимо обработаны одним публичным модулем анализа.

| Сегмент | Максимум, мг/л | Ошибка максимума, мг/л | Ошибка времени максимума, с | Ошибка первого пересечения, с | Ошибка общей длительности, с |
|---|---:|---:|---:|---:|---:|
| 36 | 10,6423189077 | 0 | 0 | −0,7055 | +1,5063 |
| 50 | 10,5662678397 | 0 | 0 | −1,0206 | +0,1968 |
| 100 | 10,4362861268 | 0 | 0 | −0,3524 | +1,7688 |

Знак ошибки: сохранённая траектория минус частая контрольная запись. В обоих рядах по одному периоду для этого порога. Максимумы и их времена совпадают точно: экстремумы входят в обязательные сохранённые состояния. Пересечения и длительности различаются: они не обязаны совпадать при сжатии траектории.

Эти числа характеризуют только конкретную демонстрацию и H=10,2. Они **не задают универсальный допуск времени**. Сохранение концентраций с допуском 1% отклонения от фона не гарантирует 1% точности пересечения: около пологого участка время чувствительно к малой ошибке концентрации. Для иных порогов/параметров нужен отдельный контроль. Погрешность численной схемы при пространственно-временном уточнении — отдельный вопрос (см. [проверки нескольких источников](multiple-sources-numerics.md)); неопределённость гидравлики и нагрузок и проверка по полевым наблюдениям этим сравнением не оцениваются. Реальными наблюдениями модель не проверена.

## Воспроизведение

Из корня проекта, с установленными зависимостями backend и frontend:

```powershell
backend/.venv/Scripts/python.exe backend/scripts/verify_control_point_analysis.py --output .cache/control-reference.json
node frontend/scripts/verify-control-point-analysis.mjs .cache/control-reference.json .cache/control-analysis.json
```

В Docker можно выполнить Python-команду внутри backend с выходом `/tmp/control-reference.json`, затем скопировать файл для Node. Скрипт не обращается к БД, не меняет решатель и не добавляет новых физических процессов. Node использует существующую поддержку TypeScript в Node 24.
