# Обзор поверхностных вод Липецкой области

Сохранённый `backend/data/regional/overview.geojson` — **картографическая
подборка**, а не полная инвентаризация поверхностных вод и не расчётная сеть
области. В ней 18 объектов: граница области, 11 именованных рек, 4 выбранных
озера и 2 водохранилища. Независимые линии расчётных участков загружаются из
существующего реестра; обзорные линии для расчёта не используются.

## Фактический охват

Граница — [relation **72169**, версия **183**](https://www.openstreetmap.org/relation/72169/history/183),
`name=Липецкая область`, `ISO3166-2=RU-LIP`, `admin_level=4`.
Это административная граница в OSM, **не юридическое описание**.

## Подготовка и проверки

Из корня репозитория, без сети, без БД и без новых зависимостей:

```powershell
backend/.venv/Scripts/python.exe backend/scripts/prepare_regional.py
backend/.venv/Scripts/python.exe backend/tests/test_regional_preparation.py
```

Нужны Python и уже используемый проектом `geographiclib==2.1`.
Скрипт читает только локальные raw/manifest, проверяет SHA-256 raw и запроса,
отказывает при замечании Overpass о неполноте ответа, проверяет имена, типы,
конечность и региональный диапазон координат. Он отвергает нулевые рёбра,
незамкнутые, вырожденные и самопересекающиеся кольца; пространственные ячейки
ускоряют проверку пересечения рёбер, не меняя геометрию. Отверстия относятся
к единственному содержащему их внешнему кольцу.

Координаты — **EPSG:4326, `[долгота, широта]`**, градусы. GeoJSON не содержит
альтернативной CRS. Каждая исходная river way сохраняется отдельной частью
`MultiLineString`, даже если её конец совпадает с соседней way. Расстояния
между концами не служат основанием для склеивания. Только объявленные OSM
участники полигональных отношений собираются по **точно совпадающим концам**;
при неоднозначности или разрыве подготовка завершается ошибкой. Порядок
колец приведён к RFC 7946; рёбра и координаты остаются исходными.

**Упрощение не применяется.** Все 19 543 координаты подготовленных частей
сохранены. Ошибка преобразования относительно сохранённых исходных линий
равна **0 м**: тесты сравнивают все вершины речных частей и мультимножество
всех рёбер полигонов, независимо от порядка и ориентации. Для тождественной
геометрии непрерывное расстояние Хаусдорфа также равно 0. Это не оценка
абсолютной точности OSM относительно местности — такая точность неизвестна.

Повторная подготовка даёт побайтово идентичный результат. Рядом записывается
`overview.sha256` с SHA-256 подготовленного файла. Набор компактно
сериализован без потери точности чисел; размер **484 913 байт** (около **474 КиБ**). Обычный
запуск читает сохранённый GeoJSON и не обращается к Overpass/OSM для его
создания. Время открытия карты и сетевой размер API проверяются отдельно
при интеграции интерфейса.

Восемь автономных тестов проверяют две повторные сборки, точный охват,
контрольные суммы и версии, соответствие каждой river way отдельной части,
полное сохранение рёбер полигонов, явное соответствие участков, отказ для
испорченного raw, неверных координат и незамкнутых/самопересекающихся колец,
а также измеренный внешний контекст и контрольную сумму результата.
Независимая геометрическая проверка PostGIS в интеграционном прогоне
подтвердила валидность всех 18 геометрий, включая внутренние кольца островов.

## Связь с расчётным реестром

Соответствия заданы явно, не определяются близостью:

- `river-don` → `don-olkhovets`;
- `river-voronezh` → `voronezh-zheltye-peski`, `voronezh-below-kuzminka`.

Эти ссылки дают доступ к **отдельно подготовленным** линиям из реестра
участков. Весь Дон или Воронеж от этого не становится расчётной сетью.
У других рек и всех водоёмов список `prepared_reach_ids` пустой, а паспорт
содержит конкретное ограничение. Никаких предприятий, выпусков и придуманных
точек координат подборка не содержит. Прежние пилотные геометрии и файлы
не изменяются этим скриптом.
