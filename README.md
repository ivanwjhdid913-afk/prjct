# Наблюдения за водой

Локальная учебная основа веб-ГИС: просмотр, поиск и фильтрация водных объектов из PostgreSQL через FastAPI и React. Реализованы загрузка, повторный запрос, пустой список, отсутствие совпадений, ошибка соединения и постраничный просмотр.

Демонстрационный набор содержит **только синтетические записи**: учебную реку, озеро и водохранилище. Они не описывают реальные объекты Липецкой области. Происхождение отмечено в базе (`is_synthetic`), API и интерфейсе. Карта, измерения и импорт в этот этап не входят.

## Требования

- Docker Desktop с работающим движком Linux-контейнеров и Docker Compose.
- Git для истории исходников.
- Для дополнительных локальных проверок: Node.js 24 LTS с npm и Python 3.14. Для запуска через Compose отдельная установка PostgreSQL и Python-пакетов не требуется.

Начальная проверенная среда: Git 2.53.0, Node.js 24.21.0, npm 11.19.0, Python 3.14.1, Docker 29.8.2, Compose 5.6.0. Точные зависимости находятся в `frontend/package-lock.json` и `backend/requirements.txt`; прямые Python-зависимости — в `backend/requirements.in`.

## Первый запуск в Windows

Откройте PowerShell в папке проекта. Создайте локальный файл настроек, только если его ещё нет:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Перед первым запуском задайте собственный пароль в поле `POSTGRES_PASSWORD` файла `.env`. Этот файл исключён из Git. При уже созданном томе базы изменение только `.env` не меняет пароль пользователя PostgreSQL.

```powershell
docker compose up -d --build --wait
docker compose exec backend python -m app.seed
```

Первый запуск скачивает образы и зависимости. Миграция применяется при старте backend. Заполнение учебными объектами выполняется отдельно и повторно не создаёт дубликаты; существующие записи не перезаписываются. Без заполнения показывается корректный пустой список.

- Интерфейс: <http://localhost:5173>
- API: <http://localhost:8000/api/v1/water-bodies>
- Описание API: <http://localhost:8000/docs>

Проверьте, что на экране три учебных объекта, их типы и маркировка «Синтетические данные». Нажмите «Обновить список». Данные приходят из базы, а не из встроенного массива интерфейса.

Введите часть названия, например `УЧЕБ`, выберите «Озёра» и нажмите «Применить» или Enter в поле поиска. Останется учебное озеро. Поиск не учитывает регистр, включая кириллицу и `ё`; пробелы по краям убираются. Пустой запрос не ограничивает название, «Все типы» не ограничивает тип. `%` и `_` ищутся как обычные символы. Поиск выполняется по подстроке, без морфологии и замены `ё` на `е`.

Изменение полей само по себе не отправляет запрос: действующие условия подписаны под формой. «Обновить список», повтор после ошибки и переходы между страницами сохраняют применённые условия. Применение или сброс возвращает на первую страницу. «Сбросить условия» очищает оба поля и сразу загружает полный список. Для проверки отсутствия совпадений совместите `РЕКА` с типом «Озёра»: интерфейс предложит изменить или сбросить условия. Пустая база имеет отдельное сообщение.

Повторный запуск: `docker compose up -d --wait`. После изменения исходников используйте `docker compose up -d --build --wait`. У frontend есть HTTP healthcheck: ожидание готовности проверяет успешный ответ страницы и наличие входного модуля интерфейса. Остановка: `docker compose down`. Именованный том с данными сохраняется. **Не добавляйте `-v` к команде остановки: этот параметр удаляет том базы.**

## Состав проекта

- `frontend/src/` — экран, состояния запросов и оформление; Vite передаёт `/api` в backend.
- `backend/app/` — подключение к базе, модель, API и отдельное заполнение учебными данными.
- `backend/migrations/` — начальная схема Alembic и включение PostGIS.
- `backend/tests/` — проверки на настоящем PostgreSQL с откатом тестовых транзакций.
- `frontend/tests/` — браузерные сценарии Playwright.
- `compose.yaml` — база PostgreSQL 18/PostGIS 3.6, backend и интерфейс.

Сервисы доступны только через `127.0.0.1`: интерфейс — порт 5173, backend — 8000, база — 55432. Это локальное окружение разработки, без авторизации и публичного развёртывания. Для интерфейса используется сервер Vite; production-сборка также проверяется при создании образа.

SQLAlchemy отвечает за запросы и ограничения модели, Alembic — за версионирование схемы, Psycopg — за соединение с PostgreSQL. Геометрия ещё не хранится, но расширение PostGIS включено. Служебные таблицы расширения исключены из сравнения Alembic; удаление собственных таблиц должно быть явно описано в миграции.

## API

`GET /api/v1/water-bodies?limit=50&offset=0&q=учеб&kind=lake`

Ответ содержит `items`, `total` (число совпадений во всей базе), `catalog_total` (число объектов без фильтра), `limit`, `offset`. У каждого объекта есть UUID `id`, `name`, `kind` (`river`, `lake`, `reservoir`) и обязательный `is_synthetic`. Записи упорядочены по названию и ID. Допустимый `limit`: 1–100; `offset` — неотрицательное целое число.

Необязательный `q` — подстрока названия, максимум 120 символов исходного параметра до удаления пробелов; нулевой символ запрещён. Необязательный `kind` допускает только `river`, `lake`, `reservoir`. Для всех типов параметр `kind` нужно опустить; пустое значение недопустимо. Условия соединяются через AND и применяются до пагинации. Лимиты проверяются на backend; SQL-шаблоны из пользовательского ввода не исполняются.

Пустая база и отсутствие совпадений возвращают `200` и `items: []`; их различает `catalog_total`. Неверные параметры поиска, типа или пагинации — `422`. Недоступность базы — `503` с нейтральным сообщением без строки подключения. Имён, координат и характеристик реальных объектов в демонстрационном наборе нет.

## Проверки

На запущенном Compose:

```powershell
docker compose exec backend python -m pytest -q
docker compose exec backend python -m pip check
docker compose exec backend alembic check
docker compose exec frontend npm run build
```

Backend-тесты временно заменяют содержимое списка внутри отдельной незакоммиченной транзакции и откатывают её после каждого теста. Сохранённые записи не удаляются. Выполняйте их в локальном учебном окружении, без одновременного изменения данных.

Браузерные тесты запускаются из Windows при работающем Compose:

```powershell
cd frontend
npm.cmd ci
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Split-Path (Get-Location) -Parent) '.cache\browsers'
npx.cmd playwright install chromium
npm.cmd test
```

Успешный сценарий и проверки размеров экрана используют настоящий API и базу с учебными записями. Пустой ответ, сетевой сбой, HTTP 503, неверный ответ и пагинация моделируются в браузерных тестах. Реальный пустой список и недоступность соединения отдельно проверяются backend-тестами. Это не проверка реальных экологических данных.

При проверке поиска и фильтров прошли 35 backend-тестов и 18 браузерных сценариев в Chromium, сборка TypeScript/Vite и проверка согласованности миграций. Проверены кириллица в разных регистрах, буквальные `%` и `_`, все типы, сочетание условий, валидация, отсутствие совпадений, сброс, пагинация и защита от запоздалого ответа. Backend-пагинация проверена на временных записях внутри откатываемой транзакции; браузерная пагинация и запоздалый ответ моделируются. Поиск и каждый тип проверены также через настоящий API с учебным набором. Содержимое сохранённых записей до и после backend-тестов совпало; все три контейнера прошли ожидание готовности.

Проверены экраны шириной 375, 768, 1024 и 1440 пикселей и управление с клавиатуры. На первом этапе также проверены сохранность записей после остановки Compose, откат и повторное применение миграции в отдельной временной базе и восстановление резервной копии с тремя записями и ревизией `0001`. Firefox, Safari, публичное развёртывание и нагрузочное тестирование не проверялись.

Если страница недоступна, проверьте `docker compose ps` и `docker compose logs --tail 50 backend frontend`. При ошибке соединения с Docker запустите Docker Desktop. При занятых портах остановите другой экземпляр этого проекта.

## Сохранение и восстановление

Исходники сохраняются локальными коммитами в рабочей ветке. Коммит не включает базу, `.env`, скачанные зависимости и результаты тестов. Для возврата к предыдущей версии кода предпочтительна отмена нужного коммита через `git revert` после проверки несохранённой работы и совместимости схемы.

Остановка и повторный запуск Compose сохраняют данные в томе `water-observation_water-data`. Резервную копию базы можно получить так (каталог исключён из Git):

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
$backupName = 'water-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.dump'
docker compose exec -T db pg_dump -U water -d water -Fc -f /tmp/water-backup.dump
if ($LASTEXITCODE -eq 0) { docker compose cp db:/tmp/water-backup.dump "backups/$backupName" }
```

Сохраняйте `.env` отдельно в защищённом месте. Перед восстановлением определите требуемые версию кода, ревизию миграций и копию базы. Сначала восстановите архив через `pg_restore` в отдельную пустую базу и проверьте результат; не перезаписывайте рабочую базу без отдельного решения. Откат миграции `0001` удаляет таблицу объектов и её данные, поэтому это не повседневный способ восстановления.
